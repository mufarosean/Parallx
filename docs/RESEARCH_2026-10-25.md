# Where the field is, 2026-10-25, and what Parallx should take from it

Web research in five areas, each by one reader: the model stack, retrieval and memory, competing products, studying with AI, and agent design with desktop polish. Every claim that matters for a decision was checked against the code on `dev` before it went in here; where the code already does what the field does, it says so. Effort: S under a day, M one to two days, L three days or more.

Source quality, honestly: several official sites did not resolve from the research container (ollama.com, huggingface.co, electronjs.org, modelcontextprotocol.io, casact.org), so some facts come from GitHub copies, release notes or secondary coverage. Those are marked *(secondary)*. Vendor benchmark numbers are vendor claims.

## The short version

1. **Parallx is less dated than it feels, but its defaults are.** FSRS-6, current Claude models, prompt caching, hybrid search with RRF, embedding prefixes, Docling, an MCP client, skills and an AI eval harness are all current practice. What a new user meets first is not: the default chat model is `qwen2.5:32b-instruct` (2024), embeddings are `nomic-embed-text` (2024), and the app runs on Electron 40, which went out of support on 2026-06-30. Changing defaults is cheap and changes the first impression most.
2. **For studying, attempt-first is the pattern the evidence backs.** Two randomized studies (about 1,000 and 2,400 students) found that AI used to get answers raised practice scores and lowered exam results; tutors that make the student attempt first were neutral to positive. The owner already studies this way: a conceptual quiz skill in the workspace has the owner answer, the AI grade, then discussion. What is missing is that the app ships this pattern to every user rather than leaving it to a skill each person writes.
3. **"Feels current" in 2026 means trust, not more AI buttons.** Every product that moved forward this year converged on the same pattern: one assistant that knows the context, edits arrive as proposals you accept or reject, background work reports to one place, answers cite their source. The complaints about Notion are AI bolted on everywhere, slow and generic. Parallx's modular rule already points the right way; the gaps are three separate logs, no single stop switch, and citations that are not checked.
4. **The bugs are partly a breadth problem.** About 400,000 lines, 18 built-in tools, 9 extensions and 116 docs, by one person. The research on finding bugs (below) helps, but the bigger lever is spending the next stretch finishing and verifying what exists rather than adding surfaces.

## Recommendations, ranked

Ranked by what the owner gets for the effort. Each says what the field does, what Parallx does today, and what to change.

### Now: small, high return

**1. Ship attempt-first study as a built-in pattern (S, impact 4).**
Field: Bastani et al. (PNAS, July 2025, ~1,000 students): unrestricted GPT-4 +48% on practice, −17% on the exam; the guarded tutor version roughly neutral. Maryland RCT (IZA DP 18989, Oct 2026, 2,379 students): offering a course tutor lowered grades 0.37 SD, about 75% of requests were for answers. Harvard physics (Sci Rep, June 2025) and World Bank Nigeria (2025) were positive, both with tutors built on pedagogy, not answer engines. ChatGPT study mode, Gemini Guided Learning, Claude learning mode and Heptabase AI Tutor all shipped this shape; none has outcome studies yet.
Parallx: the owner's conceptual quiz skill (a workspace skill, not in the repo) already runs answer, grade, discuss. Nothing in `src/` or `ext/` offers it to a new user; the shipped default chat answers whatever it is asked.
Change: package that skill's flow so a study tool contributes it through a generic composer-mode contribution point (the core names no tool), and let Worksheets open its problems in it. Correction, 2026-10-25: an earlier draft of this item said Parallx had no attempt-first flow; it missed the workspace skill.

**2. Modern local defaults, read from the model (S, impact 4).**
Field (Oct 2026): llama3.2 and qwen2.5/qwen3 are superseded. Current picks: Qwen3.5 9B / Gemma 4 E4B for 8 GB; Gemma 4 12B, gpt-oss-20b or Gemma 4 26B-A4B for 12–16 GB; Qwen3.8-27B (Q4, ~17 GB) or Gemma 4 31B for 24 GB *(sizes partly secondary)*. Ollama exposes capabilities and `thinking.values` through `/api/show`; Ollama's own embedding docs now use `embeddinggemma`.
Parallx: `DEFAULT_MODEL_CONFIG.chat = 'qwen2.5:32b-instruct'` (`src/services/parallxConfigService.ts:59`), a 32B model that does not fit most machines and predates current tool calling.
Change: pick the default by detected VRAM from a short table, and read tools/vision/thinking from `/api/show` rather than hard-coding. Keep `:cloud` models and Ollama web search opt-in and labelled as leaving the machine.

**3. Electron 40 → current supported line (S–M, impact 4).**
Field: Electron 40 has been end of life since 2026-06-30 (no Chromium security fixes). Recent lines boot the main process from a Node snapshot, about 40% faster to first JS *(Electron PRs 51703, 52873)*. Electron 45 removes `events`, `timers` and `url` from sandboxed preloads.
Parallx: `electron@40.2.1` (`package-lock.json`); the main window runs `sandbox: false` (`electron/main.cjs:675`), so the preload removal mostly does not bite, but the sandboxed frames should be checked.
Change: upgrade one line at a time, with the full checks and both accessibility probes after each.

**4. Claude provider: the 2026 knobs (S, impact 3).**
Field: `output_config.effort` (Opus 5.5 defaults to medium), refusal stop reason with fallbacks, server compaction and context editing (`clear_tool_uses`), tool search with deferred loading, structured outputs and `strict` tools, Citations on documents. *(From the bundled Claude API reference, 2026-10-06.)*
Parallx: none of `effort`, refusal handling, compaction, context editing or citations appears in `anthropicProvider.ts` or `electron/anthropicBridge.cjs`.
Change: set effort per task (low for maintenance jobs, higher for chat), handle `refusal` visibly, turn on context editing for long agent runs. One claim to verify before relying on it: a report that newer accounts get a 400 on Opus/Sonnet 5.5 when earlier turns' thinking blocks are dropped from history; Parallx re-attaches thinking only to tool turns and strips it on retry.

**5. JSON schema instead of `format: 'json'` (S, impact 3).**
Field: Ollama structured outputs take a JSON schema and constrain decoding to it.
Parallx: several callers still pass `format: 'json'` and then parse and retry (`src/services/lineageClassifierService.ts:383`, `ext/budget/main.js:6694`, `ext/creations-ai/studio.js:1276`, `ext/creations-ai/acts-panel.js:139`). The Creations commits of 2026-10-23 ("reads the forms models write, and stops retrying after three") are exactly the bug class a schema removes.
Change: pass the schema through `sendChatRequest`; keep the parser as a fallback for providers that ignore it.

### Next: medium, the core of "feels current"

**6. Answers that cite, and citations that are checked (M, impact 5).**
Field: NotebookLM's whole product is source-only answers whose citations jump to the passage. Anthropic's Citations API returns character or page ranges. ALCE (EMNLP 2023): prompted 7B models had ~17% citation recall vs ~73% for a strong model; RAVine (2025): citation precision/recall ~12–13% even for Qwen3-32B. Small models cite badly, so code has to check them.
Parallx: 42 files mention citations and `openclawCitationCheck.ts` exists; the question is whether every cited span is verified against its passage and whether a click lands on the PDF page or the block.
Change: numbered passages, `[n]` markers, a code check that each quoted span exists in passage n (drop or flag the rest), and click-through to page and highlight. A "from my sources only" switch.

**7. Move indexing to a utility process (M, impact 4).**
Field: Electron's `utilityProcess` with a `MessagePort` to the renderer, its own SQLite connection in WAL mode; better-sqlite3 recommends one connection per worker.
Parallx: `docs/Future_Improvements.md` records the freeze: the pipeline runs on the renderer thread and can make the window "Not Responding".
Change: as written there, but in a utility process rather than a renderer worker, so it can be killed and restarted without touching the UI. This also makes item 9 safe.

**8. A retrieval golden set from the owner's own material (M, impact 4).**
Field: Chroma's generative benchmarking (2025): an LLM writes realistic queries for known chunks; score recall@10 and MRR with no judge needed. Anthropic: if a knowledge base is under ~200k tokens, put it in the prompt instead.
Change: 50–150 queries over Exam 7 papers plus ~20 hand-written, a script that prints recall@10 and MRR, run before and after every retrieval change. Items 9 and 10 are judged by it, not by feel.

**9. Better embeddings and a reranker, in process (M, impact 3, needs re-index).**
Field: Qwen3-Embedding-0.6B and EmbeddingGemma (and EmbeddingGemma 2, Oct 2026, *secondary*) are well ahead of nomic v1.5 on MTEB; Qwen3-Reranker-0.6B has ONNX builds. `onnxruntime-node` is already a dependency.
Parallx: `nomic-embed-text` through Ollama with `truncate: true` (`src/services/embeddingService.ts:27`, `:372`), so retrieval stops when Ollama is down.
Change: embed in process through ONNX; add the reranker only if the golden set shows good passages found but ranked low.

**9a. Fit FSRS to the user's reviews, add fuzz and a deadline plan (M, impact 4).**
Field: srs-benchmark (~10k collections): parameters fitted to the user's own history matter more than FSRS version; FSRS-7 with defaults is worse than fitted FSRS-6. Fitting is available as WASM (`@open-spaced-repetition/binding`). Anki 25.07+ has load balancing and Easy Days; RemNote's Exam Scheduler sweeps every card once before the exam and compresses relearning.
Parallx: hand-written FSRS-6 with default parameters only, no fuzz (`ext/flashcards/main.js`).
Change: fit monthly once ~300 reviews exist, add fuzz and a simple load balancer, and simulate the workload to the exam date with a warning when it cannot be done. FSRS-7 can wait until ts-fsrs 6 is stable.

**10. One "what the AI did" timeline and one stop switch (M, impact 4).**
Field: background work reports to one feed (ChatGPT Pulse, Notion triggered agents); OpenTelemetry GenAI spans (agent, tool, plan) are a reasonable shape; Claude Code checkpoints before each edit.
Parallx: Activity, Autonomy and Indexing are three logs (`docs/LAUNCH_READINESS.md` §3.6).
Change: one local event stream with a source filter, one control in the status bar that pauses heartbeat, routines, subagents, browser and MCP at once, and "Undo AI changes" per turn for pages and data.

**11. AI edits as proposals everywhere (M–L, impact 4).**
Field: Tana proposals, Capacities approvals, Obsidian agent patches, Word and Excel Agent Mode (Excel's agent scored 57% where experts scored 71%, which is why review matters).
Parallx: Keep/Undo margin marks exist for some canvas edits; `docs/IDEAS_2026-10-23.md` "One AI On A Selection" already plans to route inline AI through the chat with these marks.
Change: make every agent write to a page, database or card arrive the same way, and never silently.

**12. Untrusted content cannot drive actions (M, impact 4).**
Field: Meta's "Rule of Two" (Oct 2025): in one session an agent holds at most two of untrusted input, private data, and the power to change things or send out. OpenAI says browser prompt injection may never be fully solved. Claude Code's auto mode judges actions on user messages and tool calls only, never tool output.
Change: tag web, MCP and email results as untrusted in code; a turn that read untrusted content needs approval for writes and egress; the heartbeat never reads the web and acts in the same turn.

**13. Fewer tools per turn for local models (M, impact 3).**
Field: Anthropic's tool search cut context 85% and raised accuracy 49%→74%; one or two usage examples per tool raised parameter accuracy 72%→90%; for small models, showing only the tools relevant to the step helps most (ACL Findings 2026).
Change: select 5–10 tools per turn by the active skill or by retrieval over tool descriptions; add examples to the most-missed tools.

**14. A generic OpenAI-compatible provider (M, impact 3).**
Field: LM Studio, llama.cpp server, Lemonade, Foundry Local, vLLM, MLX servers, OpenAI, Gemini and OpenRouter all speak it.
Change: base URL, optional key, model list; one provider instead of one per vendor.

### Study features with the best evidence-to-effort

These belong in Flashcards and Worksheets (extensions), registered through contribution points.

- **Rubric grading on the CAS model (M).** CAS now publishes Exam 7 practice items with a full-credit answer, why it earns full credit, and common mistakes *(seen in search snippets; casact.org unreachable)*. LLM grading of written answers agrees with humans only moderately and worst on judgment points; checklist rubrics agree best. Grade point by point, show each point awarded or missed, let the owner override.
- **Readiness per learning objective (M).** What Coaching Actuaries Adapt and the medical question banks charge for: tag cards and problems by paper or objective; a heatmap from FSRS recall predicted at exam day plus practice scores; a daily plan from the weakest, interleaved.
- **Confidence before reveal and an error log (S).** Rate confidence before seeing the answer; confident-and-wrong goes first. Log each missed point by kind (concept, formula, misread, time).
- **AI card drafts the owner edits (S).** Making your own cards beats premade (Pan et al. 2023, d≈0.29–0.45; one study found no effect). Drafts are atomic, single-answer and linked to the source; no bulk accept by default; an ambiguity check before saving.
- **Timed, interleaved mock exams from imported past papers (M).**

### Finding the bugs a solo developer misses

- **Property-based editor tests (M).** fast-check's model-based testing with Vitest: random sequences of edits, undo and redo on the canvas, checking invariants (doc valid, round-trips to markdown, undo restores).
- **A scripted exploratory pass (S each time).** Claude Code drives the app through a fixed checklist: first run, Ollama down, huge page, kill mid-stream, keyboard only, touch. Each run writes what broke.
- **Local crash dumps (S).** `crashReporter.start({ uploadToServer: false })` and a Copy Diagnostics command.
- **Timing budgets (S).** `performance.mark` on startup and key interactions; budgets of 100 ms for input, 200 ms for a view switch; fail a probe when exceeded.

### Later, or only with a reason

- **Optional speech (M–L).** Parakeet or Moonshine for dictation and Kokoro for reading aloud, in process through ONNX, as a tool that is off by default.
- **Page OCR for formula-heavy PDFs (M).** Small OCR models (PaddleOCR-VL, GLM-OCR, granite-docling) lead current document benchmarks; Docling remains the safest licence. Marker's weights carry a revenue-limited licence; check MinerU's added terms.
- **MCP client to the 2026-07-28 spec (M).** Stateless core, `input_required` instead of server-to-client requests; Roots, Sampling and HTTP+SSE deprecated. Do not build sampling or roots. MCP Apps (sandboxed UI) can wait.
- **An MCP server for the study desk (M).** Heptabase, Capacities, Obsidian (CLI) and tldraw all let outside agents reach their data in 2025–26; this is what would let Claude Code read and write Parallx pages.
- **SKILL.md and AGENTS.md as import formats (S).** The skills format is an open standard (Dec 2025) adopted by most agent tools.
- **Signing, notarization and auto-update** before builds go to anyone else. Windows certificates are capped at 460 days since 2026-03-01.

### Skip

GraphRAG/LightRAG (often loses to plain retrieval on fact lookup, costly to build with an 8B model), ColPali page vectors (~750 vectors a page), Mem0/Zep-style memory services (benchmarks disputed; plain files plus search did as well), audio or video overviews, a browsing agent that acts for the user, A2A, credit metering, and AI buttons on every surface. Reor, the local-AI notes app, was archived in March 2026: local AI alone is not a product; the study desk is.
