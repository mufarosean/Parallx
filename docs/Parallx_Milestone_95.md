## The install blocker, and what it actually was

`npm install` hung indefinitely, writing nothing, with no error. A direct TLS
probe named the culprit precisely:

```
subject: CN = npmjs.org
issuer : CN = Norton Web/Mail Shield Root
         OU = generated by Norton Antivirus for SSL/TLS scanning
```

**Norton Antivirus intercepts HTTPS and re-signs every certificate.** Its root
is in the Windows certificate store, so browsers are fine — and so is pip,
because Python uses the system store on Windows. Node is the outlier: it ships
its own bundled CA list and ignores the Windows store entirely, so only
Node/npm break.

**Fix:** `NODE_OPTIONS=--use-system-ca` (Node 22.15+; this machine is on
22.18). Certificate verification stays fully on — Node just reads the store
that already contains Norton's root. The install went from hanging forever to
26 packages in 2 seconds.

Deliberately not done: `npm config set strict-ssl false` or
`NODE_TLS_REJECT_UNAUTHORIZED=0`. Both would have unblocked the build by
disabling certificate verification for every future install on the machine.

**Two process lessons worth keeping.** First, npm's silence is the trap: it
does not surface TLS failures, so "slow" and "permanently broken" look
identical. Probe the socket after a minute rather than waiting. Second, the
first diagnosis here was a guess ("something is intercepting, go hunt for a CA
file") that got written into a document as if it were a finding. Thirty
seconds of `tls.connect` produced both the exact culprit and a better fix.

## What was built

**`src/ui/codeEditor.ts` + `codeEditor.css`** — THE code-editing surface.
One primitive, every consumer: the file pane uses it per file, the notebook
(M96) will use one per cell. Same rule as `api.ui.createDropdown`,
`scrollbarReveal`, and `rafThrottle` — exactly one place knows how code is
rendered, themed, and keyboard-handled.

- **CodeMirror 6, not Monaco.** Monaco *is* VS Code's editor and would bring
  TypeScript IntelliSense for free, but it also brings its own scrollbars,
  context menus, find widget, and theming system — each of which fights an
  invariant this codebase spent milestones establishing. CodeMirror styles
  from ordinary CSS, so `--px` tokens drive it, and its scroller participates
  in the app-wide scrollbar-reveal delegation with no wiring at all (it is
  found by overflow detection; the CSS deliberately sets no
  `::-webkit-scrollbar` rule and no `scrollbar-width`, either of which would
  break that).
- Lazy per-language grammar loading — a workspace that only opens `.json`
  does not pay for the Python parse tables.
- `setValue` vs `setValueAsEdit` is a deliberate pair: a reload from disk must
  **not** echo back as a user edit (it would re-dirty the file and race the
  write that produced it), while formatting must be undoable and saveable.
- `autoHeight` mode exists for the notebook-cell shape: grow with content, let
  the surrounding document own the scroll.
- `extraKeymap` lets a consumer bind Shift+Enter without the primitive
  knowing what a cell is.

**`src/built-in/editor/codeEditorPane.ts` + `.css`** — the pane. Sits
*alongside* `TextEditorPane` rather than replacing it, exactly as
`markdownEditorPane` / `excelEditorPane` / `pdfEditorPane` already coexist.
TextEditorPane is a textarea with a hand-rolled gutter and minimap: the right
tool for a `.txt` or a log, and structurally incapable of highlighting, since
the text you edit *is* the text you see. Gutting 800 lines of working code to
retrofit it would have been the riskier change. Plain text is untouched.

Pane owns: input binding, dirty tracking, a Format action, a Run action
(saves first — running the buffer means tracebacks cite line numbers in a file
that does not exist), and the status line.

## Also in this milestone

These have no CodeMirror dependency.

**`--px-syntax-*` tokens** (`src/theme/px-tokens.css`, dark + light). Before
this, the only syntax colours in the app were hardcoded hexes behind
`--vscode-*` fallbacks in `canvas.css` — unreachable by any theme. Roles, not
languages, so any highlighter maps onto them.

*Follow-up, deliberately not done:* migrating canvas's `.hljs-*` rules onto
these tokens is a ~10-line colour swap that would unify the two, but it
changes canvas's appearance and was not asked for.

**Python source formatting** (`electron/pythonBridge.cjs`,
`electron/preload.cjs`, `src/services/pythonEnvService.ts`). Formats through
`black` or `ruff` in the workspace's own environment — a natural extension of
M94, since the formatter is just another workspace-local package.

- Source goes in over **stdin** and comes back on stdout. The buffer is never
  written to disk, so formatting an unsaved editor cannot leave a temp file or
  race the user's save.
- A **closed allowlist** (`FORMATTERS`), not a general "run any module" entry
  point. Technically equivalent — `-m <anything>` is arbitrary code execution
  either way — but a general runner invites callers that skip the consent
  gate, whereas formatting a buffer the user is already editing is narrow and
  obviously safe.
- `availableFormatters()` probes with `importlib.util.find_spec`, and the
  "none installed" message names the fix rather than merely reporting failure.

Reached from the pane's Format button.
