Title bar and breadcrumbs

Two mockups: where Search Commands should live so the title bar is calmer, and breadcrumbs sized for the strip they sit in. The other fixes you raised are already in (settings menu flush with the gear, the empty editor's shortcuts as plain text, 12px status bar).

1. Search Commands

Today it is a 360px field with a keycap chip, the widest and busiest thing in the title bar, for something used now and then. It is also already in the gear menu (Command Palette…), on Ctrl+Shift+P, and in the empty editor's hints.

Today

A. Same place, quieter

  • No box, no keycap: a faint "Search" with its magnifier, 240px, centred. Pointing at it lights it and shows the shortcut as plain text (second half of the strip above).
  • Keeps the click target where people already look; still the centre of the bar.

B. An icon on the right, the open file's name in the centre Recommended

  • A magnifier icon joins the layout toggles on the right, same size and style as them. Its tooltip reads "Search Commands (Ctrl+Shift+P)". It is shown pointed at, above.
  • The centre shows what you are looking at, quietly: the open editor's name and its workspace (as macOS and Windows apps title their windows). Nothing to press there; it just answers "where am I".
  • The title bar goes from three kinds of control to two, and nothing in it is a chip.

C. Gone from the title bar

  • The centre is empty. Commands stay on Ctrl+Shift+P, in the gear menu, and in the empty editor's hints.
  • The calmest, but a mouse-only user has to know the gear menu has it.

2. Breadcrumbs

Today the file editor's breadcrumbs are 13px in a 32px strip, the same size and colour as the text you are editing, and start with the full workspace folder name. The canvas strip is also 13px. Both read as content, not as a path.
